from .models import Comment
from .serializers import CommentSerializer

### POST method
- POST(단일 댓글 생성)
1. url 및 view 함수 작성
```python
# articles/urls.py
urlpatterns = [
    ...,
    path('articles/<int:article_id>/comments/', views.comment_create),
]

# articles/views.py

@api_view(['POST'])
def comment_create(request, article_id):
    # 게시글 먼저 조회
    article = Article.objects.get(pk=article_id)
    # 사용자가 입력한 댓글 데이터를 받아서 직렬화
    serializer = CommentSerializer(data=request.data)
    # 유효성 검사
    if serializer.is_valid(raise_exception=True):
        serializer.save(article=article)
        return Response(serializer.data, status=status.HTTP_201_CREATED)
```
- serializer 인스턴스의 save 매서드는 특정 Serializer 인스턴스를 저장하는 과정에서 추가 데이터를 받을 수 있음.

2. http://127.0.0.1:8000/api/v1/articles/1/comments/ 응답 확인
3. 400 BAD request 확인 : CommentSerializer에서 외래 키에 해당하는 article field 또한 사용자로부터 입력받도록 설정되어 있기 때문에 누락되었다고 판단함. -> article field를 읽기 전용 필드로 설정해야 함.
4. serializers.py 수정
```python
# articles/serializers.py

class CommentSerializer(serializers.ModelSerializer):
    class Meta:
        model = Comment
        fields = '__all__'
        # 읽기 전용 필드로 설정하는 과정(유호성 검사에서는 제외하고, 데이터 조회 시에는 출력하는 필드)
        read_only_fields = ('article', )
```
- 읽기 전용 필드 : 서버가 조회 요청에 대한 응답 시에만 값을 표시하는 필드
- 사용 목적 : 클라이언트 측에서 수정하면 안되는 경우, 입력은 받지 않지만 정보를 제공해야 하는 경우

### DELETE & PUT
- view 함수 작성
```python
# articles/views.py

@api_view(['GET', 'PUT', 'DELETE'])
def comment_detail(request, comment_id):
    # 댓글 조회
    comment = Comment.objects.get(pk=comment_id)
    if request.method == 'GET':
        # 직렬화
        serializer = CommentSerializer(comment)
        # 댓글 데이터 추출
        return Response(serializer.data)
    elif request.method == 'PUT':
        serializer = CommentSerializer(comment, data=request.data)
        if serializer.is_valid(raise_exception=True):
            # 여기서는 넣어 줄 필요가 없는게 이미 위에서 comment를 넣었기 때문에 외래 키 데이터를 넣을 필요 없다.
            serializer.save()
            return Response(serializer.data)
    elif request.method == 'DELETE':
        comment.delete()
        return Response(status=status.HTTP_204_NO_CONTENT)
```
2. http://127.0.0.1:8000/api/v1/comments/{{ comment_pk }}/ 응답 확인


# 응답 데이터 재구성
- 댓글 조회 시 게시글 출력 내역 변경 : 게시글 번호 뿐만 아니라 게시글의 제목까지 제공하기
```python
# Comment 모델은 Article을 참조하고 있다
class Comment(models.Model):
    article = models.ForeignKey(Article, on_delete=models.CASCADE)
    ...
# CommentSerializer는 Comment의 정보를 가지고 있다.
class CommentSerializer(serializers.ModelSerializer):
    class Meta:
        model = Comment
        ...
# 하지만 CommentSerializer는 Comment의 정보만 가지고 있을 뿐, Article에 대한 정보는 없다.
# article의 정보를 포함하면서 title 필드의 정보만 반환하는 Serializer를 별도로 정의해야 한다.

# articles/serializers.py
class ArticleTitleSerializer(serializers.ModelSerializer):
    class Meta:
        model = Article
        fields = ('title',)
```
- ArticleTitleSerializer는 어디에 정의해야 할까? -> CommentSerializer 안에서 정의
```python
# articles/serializers.py
class CommentSerializer(serializers.ModelSerializer):
    class ArticleTitleSerializer(serializers.ModelSerializer):
        class Meta:
            model = Article
            fields = ('title',)
    
    article = ArticleTitleSerializer(read_only=True)

    class Meta:
        model = Comment
        fields = '__all__'
        # 위에 다른 serializer를 정의하는 순간 밑의 read_only_fields가 정의되지 않으므로 위에다가 따로 정의함.
        # read_only_fields = ('articles',)
```
- http://127.0.0.1:8000/api/v1/comments/1/ 응답 확인



# 역참조 데이터 구성
- Article -> Comment 간 역참조 관계를 활용한 JSON 데이터 재구성
- 요청사항 : 단일 게시글 조회 시 해당 게시글에 작성된 댓글 목록, 개수도 함께 붙여서 응답

### 단일 게시글 + 댓글 목록
- Nested relationships(역참조 매니저 활용)
- commnet_set으로 id 와 content도 같이 참조를 하겠다.라는 선언
```python
class ArticleSerializer(serializers.ModelSerializer):
    class CommentDetailSerializer(serializers.ModelSerializer):
        class Meta:
            model = Comment
            fields = ('id', 'content',)
    
    comment_set = CommentDetailSerializer(many=True, read_only=True)

    class Meta:
        model = Article
        fields = '__all__'
```
-> http://127.0.0.1:8000/api/v1/articles/2/ 응답 확인

### 단일 게시글 + 댓글 개수
- 기본적으로 게시글(Article)을 조회하면 참조 중인 댓글의 개수를 알 수 없다.
- 댓글 수 응답하려면 직접 계산해야함.
- View 로직 개선 : annotate 사용, num_of_comments 필드를 추가

```python
# articles/views.py
from django.db.models import Count

@api_view(['GET', 'DELETE', 'PUT'])
def article_detail(request, article_pk):
    article = Article.objects.annotate(num_of_comments=Count('comment')).get(pk=article_pk)
```
- annotate를 사용하여 추가한 주석 필드를 serializer에 추가하려면?
- fields = '__all__' 만으로는 annotate된 필드가 포함되지 않음.
- __all__은 모델의 필드 기준으로 작동하기 때문에 annotate로 만들어진 필드는 여기에 포함되지 않음.
- 동적으로 개선된 필드를 정의하려면 serializer를 개선해야 함.(SerializerMethodField 사용)
```python
# articles/serializers.py

class ArticleSerializer(serializers.ModelSerializer):

    ...
    num_of_comments = serializers.SerializerMethodField()

    class Meta:
        ...

    def get_num_of_comments(self, obj):
        # obj는 Serializer가 처리하는 Article 인스턴스
        # view에서 annotate한 필드를 그대로 사용함.
        return obj.num_of_comments
```
-> http://127.0.0.1:8000/api/v1/articles/3/ 응답 확인


#### SerializerMethodField
- Serializer에서 추가적인 데이터 가공을 하고 싶을 때 사용
- 동작 원리 : Serializer 클래스 내에서 필드로 선언하면 DRF는 get_<필드명>이라는 이름을 가진 메서드를 자동으로 찾는다.
- 주의사항 : POST, PUT 요청 시에는 사용되지 않음.
- 목적 : 유연성, 가독성, 유지보수성, 일관성

### API 문서화
- OpenAPI Specification(OAS) : RESTful API를 설명하고 시각화하는 표준화된 방법
- 도움을 주는 오픈소스 프레임워크 종류 : Swagger, Redoc
- 문서화 활용(drf-spectacular 라이브러리)

1. DRF 위한 OpenAPI 생성을 도와주는 라이브러리 설치
```
pip install drf-spectacular
```
```python
# settings.py

INSTALLED_APPS = [
    ...,
    'drf_spectacular',
    ...,
]
```
2. 관련 설정 코드 입력 및 url 작성
```python

    # YOUR SETTINGS
    'DEFAULT_SCHEMA_CLASS': 'drf_spectacular.openapi.AutoSchema',
}
# drf/urls.py
from drf_spectacular.views import SpectacularAPIView, SpectacularRedocView, SpectacularSwaggerView

urlpatterns = [
    ...,
    # Optional UI:
    path('api/schema/swagger-ui/', SpectacularSwaggerView.as_view(url_name='schema'), name='swagger-ui'),
    path('api/schema/redoc/', SpectacularRedocView.as_view(url_name='schema'), name='redoc'),
]
```
